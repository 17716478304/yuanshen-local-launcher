## 独立源码审查

独立多轮审查与开发者补充检查发现 11 项问题，均已修复并复查通过：

| 问题 | 修复 |
| --- | --- |
| 旧应用未退出导致重新打开失效 | 重启 helper 等原应用 PID 退出后启动 |
| 异常退出后未等待原 Wine，恢复依赖联网 | 获取运行锁，先等待 Wine 并恢复文件，再读取在线清单 |
| 恢复下载重复要求完整安装容量 | 按已校验文件计算剩余下载与临时容量 |
| 更新取消没有完整传播 | curl、差分、新文件与删除阶段检查取消信号 |
| 失败任务集合在客户端实例间共享 | 每次实例创建独立集合和清单状态 |
| aria2 失败或缺文件的完成记录无法重试 | 清除失效记录并重新创建下载 |
| 分块/差分缓存路径可能逃逸 | 严格单文件名和解析后的目录边界检查 |
| 差分校验失败仍覆盖原文件 | 删除损坏临时输出并返回，保留原文件，补回归检查 |
| 上游国服差分更新未实现 | 安装、更新、修复统一使用国服完整清单 MD5 同步 |
| 24 小时元数据缓存可能更新到旧版本 | 任务开始刷新 JSON/zstd 清单，保留分块与部分下载 |
| 更换 Wine 跳过旧运行时恢复并删除活跃 prefix | 按现有 Wine 文件创建恢复对象，等待进程退出并恢复；安装器拒绝残留补丁，校验新包后才替换 |

补充审查通过：bootstrap 使用 execve 保留 macOS 应用 PID 和实例锁。已核实固定 Neutralino 版本启动子进程前关闭非标准文件描述符，锁不会传播给服务、Wine 和重启 helper；实机 lsof 确认仅主应用持有锁。

未发现剩余已确认源码阻断项或新增本地服务暴露问题。此结论不是实际游戏运行验收。

## 退出进程专项二次审查

独立审查代理检查并复查了以下修复：

1. 等待 `wineserver -w` 时重复执行同一 WINEPREFIX 的 `-k`，覆盖晚连接；只对 `-k` 接受已无 server 的返回码1，`-w`仍必须成功。
2. 窗口查询限时，手动停止可绕过挂起查询，自动停止触发后保持决定。
3. 恢复未完成时，后端保留运行互斥；安装、修复和迁移被阻止，前端保留清理重试入口。
4. macOS窗口缓存导致退出误判，改用现有 Wine Windows窗口表查询，无额外二进制依赖、不附加调试器。
5. 未知类名与损坏行返回unknown；不会因连续读取失败而结束仍在运行的游戏。先完整检查可见Unity窗口，再处理未知行。

最后复查结论：已发现的问题均修复，本轮未发现新增源码阻断项。
29项前端与33项后端检查通过。真实启动、非强制窗口关闭、6文件恢复、无残留进程及再打开应用通过；完整GUI按钮和实际外接盘迁移仍待验证。

## 后台暂停场景复查

2026-10-02 将当前本地启动器的退出监测从 WebView 轮询改为原生服务线程。独立审查指出并复查了三项修复：

1. 取消旧监测后必须等待线程退出并重新检查恢复状态；仍在退出时保持409及启动互斥。
2. 查询异常将当前状态置为unknown并清零连续关闭计数；查询返回后再次检查取消，避免误杀和旧线程复活运行环境。
3. 自动清理开始与完成分开；失败或取消不得标为成功，前端不吞掉真实失败。

复查结论：上述修复通过，未发现新增源码阻断项。随后使用打包的原生后端和真实游戏，暂停前端30秒验证后台清理，再恢复前端验证文件恢复及退出码0。34项前端、39项后端检查通过。900p的最终视觉留白及实际外接盘迁移仍待用户实测。
